This directory vendors a subset of [libsoundio](https://github.com/andrewrk/libsoundio)
(MIT licensed, see `LICENSE`), imported from upstream tag `2.0.1-7`
(commit `8accf164afcb4273dbb6236b04de4dff536ef883`, 2024-04-10).

Only the files needed for the **WASAPI**, **ALSA**, **CoreAudio**, and
**dummy** backends are included (see `../CMakeLists.txt` for the exact
source list); the `pulseaudio`/`jack` backends and the upstream
`example`/`test`/`doc` trees were left out to keep the vendored subset
and its build dependencies minimal. `coreaudio.{c,h}` were added
2026-08-06, from the same pinned commit as everything else here (no
version skew) -- unlike the other backends this one has only been
verified by cross-compiling/linking against a real macOS SDK, not by
actually running it (no Apple hardware was available to test on).
`config.h` is generated by CMake from
`src/config.h.in` at configure time (`SOUNDIO_HAVE_WASAPI` only when
targeting Windows, `SOUNDIO_HAVE_ALSA` only when `find_package(ALSA)`
succeeds on a non-Apple non-Windows target, `SOUNDIO_HAVE_COREAUDIO`
only when targeting Apple), not committed.

PulseAudio wasn't added alongside ALSA: on a modern Linux system where
PulseAudio (or PipeWire) is the actual sound server, ALSA client
applications still work transparently through its own ALSA-compatible
plugin (`libasound_module_pcm_pulse.so` / the PipeWire ALSA shim), so a
separate PulseAudio backend would be mostly redundant for this app's
purposes. Revisit only if a real setup surfaces where that
compatibility layer doesn't work.

To pull in another backend later, copy its `src/<backend>.{c,h}` from
upstream and add it (gated by the right platform/library check) in
`../CMakeLists.txt`'s libsoundio target.
